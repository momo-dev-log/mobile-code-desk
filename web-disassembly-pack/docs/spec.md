# Web解体パック v0.1 仕様メモ

## 目的

公開Webページ/Webアプリの HTML・CSS・JavaScript を取得し、
AIに読ませやすいMarkdown調査パックに変換する。

人間がスマホで長いコードを読むためのビューアではない。
AIに「このページどう作ってる？」と聞くための材料を作る梱包ツール。

主目的は、Canvas・スマホ操作（pointer/touch）・墨流し風UIの描画処理・
音声・操作バー構造の調査。

## 既存アプリとの関係

- `notebooklm-packer/` とは独立した別アプリ（`web-disassembly-pack/`）として実装する。
- フロント・Worker・デプロイワークフローはすべて専用に新規作成し、既存ファイルには触れない。

## v0.1のUI方針

- コードビューアではないため、HTML/CSS/JS本文をそのまま大量表示しない。
- 解析結果は要約カード・セクション単位で表示する。
- 最終成果物はMarkdown。
- スマホ利用を想定し、「コピーする」ボタンを最優先（大きく・上部）に配置する。
- 「.mdを保存」はコピーより優先度を下げる（あってもよいが控えめな配置）。
- 危険情報チェック欄は、Markdown生成前（生成結果の近く）に配置する。

## 操作ボタン文言

- URLを取得
- 構造を見る
- Markdownを作る
- コピーする
- .mdを保存
- やり直す

「解体する」のような強い表現はv0.1では使わない。

## 処理フロー

1. **URLを取得**
   - 専用Worker（`worker/index.js`）経由でHTMLを取得する（CORS回避・文字コード正規化）。
2. **構造を見る**
   - HTMLをDOM解析し、以下を判定する。
     - canvas / button / audio / video / svg の有無・件数
     - インライン/外部 script・style の件数
     - 外部CSS/JSの参照URL一覧（同一オリジン判定つき）
   - 外部CSS/JSを取得する（取得方針は下記）。
   - インライン/外部CSS・JSそれぞれにキーワード抜粋を作る。
   - 危険情報チェックを実行する。
3. **危険情報チェック**
   - HTML本文・インラインCSS/JS・取得できた外部CSS/JSを対象に、
     APIキーらしき文字列・メールアドレス・秘密鍵ブロック等のパターンを検出する。
   - 検出値はマスクして表示・Markdownに記録する。
4. **Markdownを作る**
   - 構造概要・危険情報チェック結果・CSS/JSセクションをまとめたMarkdownを生成する。
5. **コピーする / .mdを保存**
   - `navigator.clipboard` でコピー（最優先）。
   - Blobダウンロードで `.md` 保存（任意）。
6. **やり直す**
   - 状態をリセットし、最初の入力画面に戻る。

## 外部CSS/JS取得の制限（v0.1）

- CSS・JSそれぞれ最大5件まで取得する。
- 同一オリジンを優先し、外部オリジンのリソースはv0.1では取得対象外とする
  （Markdownには「取得対象外」として記録する）。
- 件数上限を超えた同一オリジンのリソースは「取得対象外（件数上限）」として記録する。
- 1ファイルあたり処理対象は約200KB（`MAX_RESOURCE_CHARS`）までとし、
  それを超える分は処理対象外（先頭部分のみを抜粋対象にする）。
- 取得に失敗したファイルは、理由（通信エラー/HTTPエラー/サイズ超過）とともに
  「取得失敗」としてMarkdownに記録する。

## キーワード抜粋（excerpt.js）

巨大ファイル・minify済みファイルでも全文を載せず、キーワード周辺のみ抜粋する。
該当キーワードが無い場合は、文字数と先頭部分のみの概要を記録する。

### JS優先キーワード

canvas, getContext, pointer, pointerdown, pointermove, pointerup,
touch, touchstart, touchmove, mouse, mousemove, requestAnimationFrame,
audio, play, pause, clear, reset, wash, color, palette, draw, resize
（fetch, localStorage, WebSocket は優先度低として末尾に含む）

### CSS優先キーワード

body, html, canvas, button, toolbar, controls, footer, fixed, position,
z-index, background, border-radius, backdrop-filter, display, flex, grid

## Worker（worker/index.js）

- notebooklm-packer用Workerとは完全に別名・別デプロイ（`web-disassembly-pack-worker`）。
- `GET /?url=<対象URL>` でHTML/CSS/JSいずれも取得可能。
- 文字コード判定・UTF-8正規化、サイズ上限（5MB）、タイムアウト（15秒）は
  notebooklm-packer v2 Workerと同様の方針を採用。

## v0.1成功条件

1. URLを入力できる
2. Worker経由でHTMLを取得できる
3. CSS/JSファイル一覧を抽出できる
4. canvas / button / audio / script / stylesheet の有無を判定できる
5. CSS/JSの重要キーワード周辺を抜粋できる
6. AI用Markdownを生成できる
7. スマホでMarkdownをコピーできる
8. 可能なら `.md` として保存できる

## v0.1で扱わないもの

- 複数URLの一括処理
- 履歴管理・カテゴリ分け・IndexedDB永続化
- 画像・フォント等バイナリアセットの内容取得（一覧表示のみ、v0.1では対象外）
- JS実行結果（動的DOM）の解析
- 認証が必要なページへの対応

## v0.4.0 全文つきMarkdown（PR-B）

「Markdownを作る」（通常版）はそのまま残し、別ボタン「全文つきでMarkdownを作る」を押したときだけ、
通常版の内容（メタ情報に「出力形式: 全文つき」の1行を追加）の末尾に「全文収録」の節を追加する。
通常版の出力は変えない。実装は `js/fulltext.js`。

### HTML構造枠（最大20,000文字 `MAX_FULL_HTML_CHARS`）

- script/style の本文は取り除き、`/* [WDP] 本文省略: インラインscript #N（M文字）… */` に置き換える
  （番号は parse.js と同じく、空でないインラインのものだけを数える。template内は番号を付けない）。
- 上限内ならそれ以外は元のまま。超える場合は段階的に縮める:
  1. 空白の連続をまとめ、200文字超のテキスト・属性値（data: URIなど）、120文字超のコメントを短くする（タグの入れ子は保つ）
  2. それでも超える場合、タグの境目で先頭（約8割）と末尾（約2割）を残し、中間を `<!-- [WDP] ここから N文字…を省略 -->` にする
     - 切る位置は、各予算の末尾側25%の範囲の境目から「開いている要素が最も少ない」ものを選ぶ（末尾側は先頭側との対応の崩れが最も少ないもの）
     - それでも崩れる対応は、元HTMLの要素（名前#id.class）として「終了タグが欠けた要素」「開始タグが欠けた要素（うち終了タグだけ末尾側に残るもの）」に分けて明記する
     - 欠けたタグは補わない。開始・終了タグの対応は名前による簡易計算（void要素・「/>」を考慮）で、ブラウザのDOM構築とは一致しない場合がある
     - 開いている要素の並びは親をたどる連結リストで持ち（メモリはトークン数に比例）、省略の目印が上限をはみ出す場合は
       再帰せずループで先頭側（空なら末尾側）を1トークンずつ減らす。Workerの上限（5MB）程度のHTMLでも上限内で終わる
- 元の文字数・収録文字数・短縮/切り詰めの有無を明記する。

### CSS/JS本文（合計最大100,000文字 `MAX_FULL_CODE_CHARS`）

- 対象: インラインstyle/script と、取得に成功した同一オリジンの外部CSS/JS（1ファイル解析範囲 200KiB まで）。
- 配分: CSSに40%（`FULL_CODE_CSS_SHARE`）、JSに60%。片方が使い切らない分はもう片方へ回す。
- 種類ごとに文字数の小さいものから全文収録し、入りきらない最初の1件だけ残り枠で途中まで収録する
  （残りが500文字 `MIN_PARTIAL_CHARS` 未満なら収録しない）。以降は収録しない。minify判定による除外はしない。
- 本文が完全一致するソースは最初の1件だけ収録し、残りは「同一内容」と記録する（枠を使わない）。
- 出典（インライン識別子 / URL）・元文字数・解析範囲・収録文字数・途中終了を明記する。
- 文字数の数え方: 「元の文字数」「解析範囲」「未収録」「元ファイルの○文字目」は取得した元の本文で数える。
  「収録」はマスク・制御文字の置き換え後にコードブロックへ載せた文字数（上限もこの数で数える）。置き換えがあった場合は
  置き換え前の文字数を併記する。途中収録では「解析範囲内の残り」と「元ファイル全体の残り（うち解析範囲外）」を分けて書く。
  収録がマスク表記の途中で切れた場合、その元の値は収録済みに数えない。
- HTML構造枠の置き換え文に書く本文の文字数は、parse.js と同じ数え方（改行をそろえ、前後の空白を除く）にし、
  「元の文字数」と一致させる。
- 取得失敗・外部オリジン・件数上限・文字数上限・解析上限で収録しなかったものは「収録しなかったコード」に記録する。

### 安全対策

- 全文つき版では、先頭の通常版部分もページ由来の文字列（タイトル・URL・識別子）をマスクしてインラインコードにし、
  抜粋は安全なフェンスで囲む。危険情報チェック欄には値の一部（先頭・末尾4文字）を載せない。通常版の出力は従来どおり。

- 収録内容はすべてコードフェンス内。フェンスは本文中の最長バッククォート連続より長くする。識別子はインラインコードにする。
- 危険情報チェックと同じパターン（APIキー/トークン・AWSキー・Bearer・メールアドレス・秘密鍵ブロック全体）と、
  トークン/パスワードらしい属性値（csrf・nonce・password入力のvalue など）を `[WDP:マスク済み]` に置き換える。
- 文字の向きを変える制御文字・NUL などは `[U+XXXX]` 表記に置き換え、改行は `\n` にそろえる。
- パターン照合なので、すべての機密情報を検出することはできない（Markdown内にも明記）。

## v0.4.1 全文つき版の追加取得

通常解析（「構造を見る」でCSS・JS各5件まで取得）は変更しない。全文つき版だけ、不足分を追加で取得する。
実装は `js/full-fetch.js`（計画と通信）、`js/main.js`（`handleFullMarkdown`）。

- きっかけ: 「全文つきでMarkdownを作る」を押したとき。追加取得が要らなければ通信せずにすぐ作る。
- 上限: CSS 10件・JS 20件。通常解析で取得した分を含む。1回の全文生成ごとに
  「再利用する取得成功分＋今回の通信試行（失敗・タイムアウトも1件）」で数える。
- 重複: 同じURLは1件にまとめる。取得に成功したファイル（通常解析分を含む）はURLごとに保存し、再取得しない。
- 通信: 1件ずつ。1件の待ち時間は min(20秒, 全体の残り時間)、全体で60秒。60秒に達したら残りは試行しない。
  待ち時間はブラウザ側で打ち切る（`fetchResource` の `timeoutMs`。Worker側の処理は止まらない）。
- 文字数: 追加取得した解析範囲（1ファイル最大200KiB）の合計は200万文字まで。達した通信の分は残りの文字数まで
  切り詰め、理由（追加取得の合計文字数上限）を記録する。以降は試行しない。
- 失敗の扱い: 通信失敗・タイムアウト・時間切れの未試行は成功扱いにしない（保存しない）。次に全文つきを押したとき、
  それらだけを再試行する。やり直し・再解析で途中終了した取得の結果は捨てる。
- 記録: script要素の記述順と属性（type/module/async/defer/nomodule）を `parseHtml().scriptOrder` に記録する。
  通信を試行した順の記録とは別の節に書く。
- 収録: CSS/JS本文の収録順（小さいファイル優先）と上限（HTML 20,000文字・CSS/JS 100,000文字）は変えない。
- 危険情報: 追加取得分も危険情報チェックを行い、画面（`#danger-extra-result`）と全文Markdownに通常解析分と分けて表示する。
- 表示の整合: 全文つき版の先頭（通常解析の節）は通常解析の事実を残し、ファイルごとに「→ 全文つき版: …」を書き足す。
  「全文つき版の取得状態」ではURLごとに「通常解析 / 全文つき版 / 収録」の状態を1行に並べる。
- Worker（`worker/index.js`）は変更しない。


## 現行実装メモ（v0.4.2以降、2026-11-14）

この文書の前半は**v0.1当時の設計記録**であり、現在の機能制限を示すものではない。
現在は、通常版Markdownに加え、HTML構造とCSS/JS本文を収録する**全文つきMarkdown**を生成できる。
生成したMarkdownはコピーだけでなく、スマートフォンから `.md` ファイルとして保存できる。
全文つき版ではCSS最大10件・JS最大20件を取得対象とし、1ファイルの解析上限と出力総量上限がある。
したがって**完全なソースコードの取得・再現を保証するツールではない**。

- 解析時の相対URLは、取得後の最終URLとHTMLの `<base href>` を考慮する。
- JSON-LDやimportmapなど実行可能なJavaScriptではないscriptはJS件数から除く。
- フロントの取得は通常20秒、Workerの取得は15秒でタイムアウトする。
- Workerはローカル/プライベートアドレスや不正なリダイレクト先を拒否する。ただしDNSリバインディングや大量アクセスへの完全な防御ではなく、Cloudflare側のレート制限などは別途必要。
- 機密値マスクはヒューリスティックであり、**すべての秘密情報を検出できるわけではない**。共有前の確認は必要。

### 現状の制約と次の課題

1. 長いMarkdownをチャットに直接貼り付けると、受け取り側の文字数制限で後半が欠けることがある。まず `.md` ファイル保存を利用する。
2. Vite等のバンドル済みサイトではimportの追跡、動的DOM、外部オリジンの取得が不十分。
3. 全文収録には文字数上限があるため、収録されなかったコードと理由を確認する。
4. 通常版と全文つき版の重複や出力順を整理し、AIがコードを読み取りやすい形式にする余地がある。
5. Workerの利用制限はアプリ側のURL検証だけでは完結しない。
